# Product Surface Output Contract

Use this reference to keep the product-surface brigade aligned.

Treat this summary shape as the intended product-default behavior for broad product-surface review and recommendation work, not merely a trace-validation format.

## Brigade output

When `apple-appdev-workflow:apple-product-surface-orchestrator` is active, use these sections in this order:

1. `Routing`
2. `Activated skills`
3. `Surface scope`
4. `Discovery findings`
5. `Surface assessment`
6. `Coordinated recommendations`
7. `Validation and rollout notes`
8. `Direct follow-on lanes`

Rules:

- `Routing` should be `orchestrator-led`.
- `Activated skills` should name `apple-appdev-workflow:apple-app-orchestrator`, `apple-appdev-workflow:apple-product-surface-orchestrator`, and only the additional stations that materially shaped the result.
- `Surface assessment` should summarize the main structural, hierarchy, copy, and presentation issues without creating a separate findings dump.
- `Coordinated recommendations` should preserve the ordering and dependencies across the contributing stations instead of listing disconnected lane-local advice.
- `Validation and rollout notes` should call out what still needs visual, platform, or runtime checking before implementation or rollout.
- `Direct follow-on lanes` should make the next narrow implementation or refinement owners explicit.
- Do not prepend freeform findings, redesign prose, or station-local summaries before the brigade sections.
